## Mission explanations

### Mission 1 — Edit distance

The cell `d[i][j]` is the minimum number of single-letter operations needed to change the first `i` characters of strain A into the first `j` characters of strain B. The first row and column are initialized with the number of insertions or deletions needed for an empty prefix. Each other cell is the minimum of deletion (`d[i-1][j] + 1`), insertion (`d[i][j-1] + 1`), and matching or replacing the last character (`d[i-1][j-1] + 0 or 1`). The answer is `d[n][m]`.

### Mission 2 — Longest common subsequence

A subsequence keeps the original order of characters but may skip characters; a substring must be contiguous. If the current characters match, the LCS table adds one to the diagonal cell. If they differ, it takes the larger result from the cell above or the cell to the left. Therefore the shared core can be longer than the number of characters that match at exactly the same positions.

### Mission 3 — Prefix function and KMP

The prefix function at position `i` stores the length of the longest proper prefix of the pattern ending at `i` that is also a suffix of that prefix. KMP uses this information after a mismatch, so it moves the pattern pointer back to a useful prefix without moving the text pointer backwards. The border length for my marker is **4**, meaning that the marker's longest proper prefix that is also its suffix has four characters.

### Mission 4 — Rabin-Karp

A rolling hash lets the algorithm calculate the next window hash from the previous one in constant time. Equal hashes do not prove that two strings are equal because different strings can collide, so the implementation compares the actual characters before counting a match. If many windows share a hash, these extra comparisons can make the worst-case running time much slower; with few collisions, the expected behavior is close to linear in the input lengths.

### Mission 5 — Dynamic programming on a tree

For each person `v`, the DP stores two values: the minimum cost when `v` is tested and the minimum cost when `v` is not tested. If `v` is tested, each child may be tested or not, so we take the cheaper child state; if `v` is not tested, every child must be tested to cover their connecting edge. After computing the values from leaves to the root, the program reconstructs which people to test. A greedy choice such as testing the person with the most links first is not always cheapest because it ignores the testing costs and how choices affect neighboring subtrees. The longest chain is found by keeping the two longest downward paths at every vertex and combining them.

## Complexity

Let `n` and `m` be the lengths of the two strings, `g` the genome length, `p` the marker length, `k` the shared-word window length (12 in this assignment), and `v` the number of people.

| Algorithm | Time | Space | Assumptions |
|---|---|---|---|
| Edit distance | `O(n * m)` | `O(n * m)` | Full DP table |
| LCS | `O(n * m)` | `O(n * m)` | Full DP table |
| Prefix function and KMP | `O(p + g)` | `O(p + g)` including returned hit positions | Text pointer never moves backwards |
| Rabin-Karp (shared words) | Expected `O(n + m)` hash work plus verification; worst case `O(n * m * k)` | `O(m)` | Hash collisions are verified by character comparison; `k` is fixed at 12 here |
| Tree DP | `O(v)` | `O(v)` | Input is a tree; iterative traversal avoids recursion depth issues |
